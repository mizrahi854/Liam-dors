# סרט הדלת בתלת־ממד — מסמך המשך ל־Claude Code

עודכן: 17.09.2026. המסמך מיועד לסוכן שממשיך את העבודה בלי היסטוריית השיחה. תקשורת עם המשתמש: **בעברית בלבד**.

## 1. מה המשתמש רוצה (בקשה אחרונה, מחייבת)

- סרט ריאליסטי של **הדלת הזאת בדיוק**: דלת פיבוט בחיפוי גרניט פורצלן אפור, ידית שחורה שקועה לכל הגובה, משקוף שחור דק, קיר לוחות אפור, רצועות אבן בהירה בשני הצדדים וחדר בתאורה חמה מאחור.
- **המקור לתנועה:** לוח 15 הפריימים שהמשתמש שלח (יצר אותו ב־ChatGPT) וסרטון הרפרנס `assets/references/liam-motion-reference.mp4`, בשניות 1.7–4.3. **אין להשתמש בתמונות עצמן.** הכול נוצר מחדש בתלת־ממד.
- הרצף: דלת סגורה, פתיחה, מבט מהצד על עובי הכנף, השכבות נפרדות כמו מניפה בתוך הפתח, כל שכבה יוצאת קדימה בתורה, איחוד, סגירה.
- באתר: סקשן במסך מלא שנשלט בגלילה. בהתחלה כותרת במרכז שנעלמת עם הגלילה. **לא** פסקאות הסבר מתחת לתמונה. הכיתוב קצר ומופיע על הסרט עצמו, כמו בלוח.
- המשתמש ביקש שהסוכן יבצע בעצמו ולא יעביר הלאה. הרף הוא „כמו סרט", לא „תמונות שמתחלפות".

## 3. הפעלה ובדיקה

```bash
cd site
npm run lab
```

השרת: `http://127.0.0.1:8766`. אם עובדים עם חלונית הדפדפן של Claude, הקובץ `.claude/launch.json` כולל תצורה בשם `liam-lab`.

| כתובת | מה עושה |
|---|---|
| `/lab/door-film/` | הנגן. גוללים לאורך הסרט. בקונסול: `__film.seek(0.515)` |
| `/lab/door-film/render.html?set=portrait&t=0.44` | רינדור רגע אחד לתצוגה, 40 דגימות |
| `…&save=name` | שומר JPG מלא ב־`design/renders/door-film/preview/name.jpg` |
| `…&source=procedural` | בונה את הדלת מהקוד ולא מה־GLB. חובה כשמשנים את `door-model.js` בלי לייצא מחדש |
| `/lab/door-film/render.html?set=portrait&run=1&samples=48` | רינדור 360 פריימים ושמירה (כ־3 דקות לכל סט). לשמור את הלשונית בחזית |
| `…&run=1&from=120&to=200` | רינדור חלקי. manifest נכתב רק ברינדור מלא |
| `/lab/door-film/export.html` | ייצוא `liam-door.glb` מחדש |

אחרי רינדור:

```bash
python3 site/scripts/encode-door-film.py portrait landscape
```

בדיקת האתר הקיים (עוברת):

```bash
npm --prefix site run check
```

**סדר עבודה נכון אחרי שינוי:** קודם `export.html` (אם `door-model.js` השתנה), אחר כך תצוגה עם `save=` וקריאת ה־JPG, אחר כך `run=1` לשני הסטים, ובסוף קידוד. כדאי גם גיליון ביקורת: הרצת `draw()` בכמה ערכי t מקונסול `render.html` והרכבה על canvas אחד. הדוגמה נמצאת ב־`design/renders/door-film/preview/sheet.jpg`.

## 4. חוזה המודל (לא לשבור)

- יחידות במטרים. `LiamDoor` › `Leaf` (ציר הפיבוט בראשית, ‏‎`rotation.y` חיובי מסובב את צד המנעול פנימה) › שש שכבות, מבחוץ פנימה:
  `Layer_ExteriorCladding` · `Layer_ReinforcementSheet` · `Layer_Insulation` · `Layer_SteelFrame` · `Layer_AluminiumProfile` · `Layer_InteriorCladding`
- `Hardware_Handle` נמצא בתוך השכבה החיצונית. `Hardware_Lock` ו־`Hardware_Pivot` נמצאים בתוך השלד. `Frame` הוא משקוף סטטי.
- ב־userData של כל שכבה (נשמר ב־GLB כ־extras): `spread` (תזוזה בציר Z המקומי כשהמניפה פתוחה), `fan` (סיבוב נוסף ברדיאנים), `labelHe`, `order`.
- מידות: כנף 1.4×2.45 מ׳, עובי 85 מ״מ (הנתון היחיד מתוכן הלקוח), ציר במרחק 0.42 מ׳ מהקצה.
- מודל CAD אמיתי יכול להחליף את ה־GLB, בתנאי שישמור על השמות ועל מוסכמת הציר.

## 5. ציר הזמן

ב־`scene.js`: המערך `BEATS` מגדיר 15 תחנות לפי הלוח (t, כותרת ותת־כותרת), ו־`POSES` מגדיר את המצב בכל תחנה: `open` במעלות, `explode`, `fan`, `focus` (מספר השכבה המוצגת), `present`, `cam`, `tgt`, `frame` (גודל הפריים). לכל תחנה יש השהיה קצרה (`HOLD`). האינטרפולציה היא cubic מונוטוני, בלי חריגה מעבר לערכי הקצה.

הנגן קורא את `beats` ואת `anchors` (מיקום כל שכבה במסך, לכל פריים) מתוך `manifest.json`. לכן אחרי שינוי ב־`BEATS` חייבים לרנדר מחדש.

## 6. איכות הרינדור — איך היא מושגת ומה חלש

**איך:** כל פריים הוא ממוצע של 48 רינדורים עם jitter תת־פיקסלי (anti-aliasing). בכל מעבר, אור שמיים מכיוון אחר בכיפה, כך שהממוצע נותן הצללה רכה ו־ambient occlusion אמיתיים. שמש רכה עם jitter, מנורה חמה על הקיר האחורי בפנים, מיפוי טונים AgX, ויגנט וגרעין קבוע. תבנית הדגימה זהה בכל הפריימים, כך שאין הבהובים בסרט.

**חולשות ידועות (עדיפות לתיקון):**
1. **טקסטורות פרוצדורליות.** האבן נראית טוב במרחק ופחות בתקריב. השיפור הגדול ביותר יבוא מטקסטורות PBR אמיתיות: map, normal ו־roughness לגרניט אפור, לטרוורטין ולאבן בהירה. המקום להחליף: `slateTextures` / `travertineTextures`, ולייצא מחדש.
2. **אין השתקפויות אמיתיות ואין תאורה עקיפה.** הרצפה הפנימית מבריקה אבל לא משקפת. אם צריך קפיצה ברמת הריאליזם, אפשר לרנדר את אותו ה־GLB ב־Blender (Cycles). Blender לא מותקן כרגע. גם `three-gpu-pathtracer` אפשרי, אבל הוא חבילה חדשה ויש לשאול את המשתמש לפני התקנה.
3. **קצב הסיביות של ה־MP4 נמוך** (כ־1.5Mbps, הגדרת ברירת המחדל של OpenCV). אם יש ffmpeg מלא:
   ```bash
   ffmpeg -framerate 30 -i design/renders/door-film/portrait/%04d.jpg -c:v libx264 -crf 16 -pix_fmt yuv420p -movflags +faststart out.mp4
   ```
   ה־ffmpeg של Playwright במחשב הוא בנייה מוגבלת.
4. **השכבות פשוטות יחסית ללוח:** שלד פלדה כסולם, פרופיל אלומיניום כמסגרת כפולה. אפשר להוסיף פרזול גלוי, אטמים ומנעול עם בריחים.
5. **הקו של תווית השכבה** נמתח לפעמים באלכסון מעל שכבות אחרות בדסקטופ. כדאי לעגן אותו לקצה העליון של השכבה ולא לנקודה ב־62% מהגובה.

## 7. הצעדים הבאים

1. **להראות למשתמש את שני הסרטונים ואת `/lab/door-film/`** ולקבל אישור על הכיוון לפני ליטוש נוסף.
2. לפי המשוב: טקסטורות אמיתיות, כוונון זוויות וקצב בתוך `POSES`, ואז רינדור וקידוד מחדש.
3. **שילוב באתר, רק אחרי אישור:** להחליף את הסקשן `#system` ב־`site/dist/index.html` במבנה של `lab/door-film/index.html`, לחבר את `player.js` כמודול עם טעינה עצלה (IntersectionObserver, כמו ב־`story.js`), ולהסיר את הלוח הישן ואת GSAP מהסקשן. `story.js` עדיין מטפל גם בסקשן `#details` ובנגן סרטוני הדובר, ואת אלה חובה לשמר. לעדכן את `scripts/check.mjs` ו־`check-ui.mjs`, להריץ `npm run build`, ולבדוק ב־Chromium וב־WebKit ברוחבים 390, ‏768 ו־1440, כולל מצב הפחתת תנועה.
4. משקל: 22MB של פריימים לשני הסטים. לשקול 180 פריימים (כל פריים שני) לנייד, או WebP באיכות 70. הנגן כבר טוען מגס לעדין.
5. פרסום ל־GitHub Pages (`mizrahi854/Liam-dors`, ענף main) רק לפי בקשה מפורשת. אחר כך לעדכן את `יומן-עבודה.md` ואת `docs/בדיקת-פרסום.md`.
